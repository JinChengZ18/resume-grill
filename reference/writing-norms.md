# 输出写作规范（生成面试材料时遵循）

这些约束已通过 `directive(lang)` 内置进两个分析引擎的提问词；此处备查，也供人工微调时对齐。语言相关规则按产物语言（`meta.lang`）分别生效。

## 通用（各语言均守）
- 每个逻辑段落写成单一物理行，靠渲染器软换行（Markdown 不手动硬换行）。
- 一问一答，示范回答用自然口述段落；判分依据另列。诚实说明实际范围是可信度信号，能力是否满足岗位要求另作判断。

## 中文产物（lang=zh）
- 中英文之间、中文与数字之间不加多余空格：「以Python实现」「第2章」「8个种子」；保留数字与单位间空格（`100 nm`、`0.9 V`）。
- 中文句内标点用全角（，；：、）；半角 `,;:` 仅用于数字/代码/公式/英文列表内。
- 禁用词（机翻/黑话痕迹）：交付、再生、天然、免费、回连、让渡、封顶、能量账、省下、补上、旋钮、喂、健壮、落地。按义择词替换（deliver→完成/给出/产出；land→实现/上生产；robust→稳健）。

## 英文及其它语言产物
- 英文用直白准确的技术散文；标点、间距按该语言常规，不套用中文全角/无空格规则，禁用词表不适用。
- 其它语言：全部字段用简历语言，风格自然地道即可。

## 跨语言引用（简历语言 ≠ 产物语言）
- 引用简历措辞来佐证强项/红旗时，**必须译成产物语言**，绝不照抄原文字符。英文产物里出现中文（如把简历原句 `参与`、`排查并修复生产环境中的 Memory Leak` 直接嵌进英文散文），读者根本读不了，视为缺陷。
- 反向亦然：英文简历出中文材料时，引用先译成中文；通用技术名词（FastAPI、Kubernetes、Memory Leak）保留英文原词是地道做法。
- 最易漏的字段：`anchor`（题目锚点）、`flags`、`strengths`、`opener.tell`。
- 确定性兜底：`python scripts/check_lang.py payload.json` — 非 CJK 产物出现中日韩字符即失败（文件名/链接豁免）。

## 主题、问题与回答

- 每道核心题是一个主题：项目提供背景，主问题讨论重要判断，后续问题检验理由、替代路线、代价和适用范围。技术追问归入本题的`followups`，紧接本主题显示；只有合作安排、材料确认等独立事项放在末尾。
- 对研究及高级岗位，深度体现在识别问题与比较路线的能力。更具体意味着明确目标、约束或比较对象，不等于不断追问参数、脚本、日志和计算步骤。实现证据只在影响判断时选问。工程实现审计则按用户要求展开相应细节。
- 每次追问要有承接理由：候选人主张了什么，哪个新条件值得讨论，会影响哪个结论。避免把几个相关名词串成多任务长问，也不强迫每题都走同一种逻辑。
- 礼貌、自然，避免“到底做没做”“主动承认错了”等预设失败的表达。HR转述与已证实事实分开；希望报酬、论文或自主性本身不是负面信号。
- `ladder[].answer`、`ask_answer`、`probe_answer`、`followups[].answer`各自直接回答对应问题。用候选人可口述的形式给出立场、依据与边界；不要只写“能解释某点”。本人经历未知处标明待填事实；假设例子明确标注，不冒充实测成果。
- `pass/tell`是面试官参考，独立于示范回答；不能要求与示范观点相同。问题改动后重新核对答案是否覆盖所有子问，必要时同步修改判分。
- 核查技术准确、题目逻辑与事实边界。没有实测证据的合理推测仍是推测；能力缺口、证据未确认与不诚信是不同判断。

## 层次示例

研究主题可以问：“某方法在少数任务上收益大，另一方法收益较小但更易复用。针对您想解决的问题，会优先研究哪条路线，为什么？”追问应继续讨论适用范围、选择代价或改变判断的证据，并放在这一主题内。只有候选人的论据依赖某个实验口径时，才确认那项口径；不要自动把话题引向工具排错。

## 图形/HTML
- 卡片页与评分卡完全自包含（内联 CSS/JS，无任何外部/CDN/字体依赖）。
- 跨文件链接一律用**本地相对路径**（同目录文件名），可 `file://` 直接打开。
- 明暗主题自适应；限时模式评分卡打印为A4、一位候选人一页，ultra模式可以跨页但不拆分单行；表头用深色字+浅底，关掉「背景图形」也可读。
- 每个主题内按“问题→可折叠示范回答”显示，追问也采用同样结构；折叠全部答案不能隐藏追问。Markdown保持同样的主题归属与问答顺序。
